## 1. Что делаем

Веб-сервис, где сотрудники находят друг друга в команды по Dota 2 и League of Legends.
Три роли: **капитан** (собирает), **игрок без команды** (ищет), **админ/организатор** (видит всё, проверяет, выгружает).

Работает **в обе стороны**: не только «игрок стучится в команду», но и «капитан находит свободного игрока и зовёт». Без второго половина сценариев мертва — сильный саппорт просто сидит и ждёт.

3. Деплой по образцу существующего `cf.conf`: systemd + nginx reverse-proxy + `certbot --nginx`.
4. Корпоративная сеть банка может резать CDN — **все ассеты (CSS/JS/шрифты) только локально**, никаких внешних ссылок.

## 4. Доменная модель по играм

Дисциплина — **конфиг, а не хардкод** (`games/dota2.py`, `games/lol.py`): роли, шкала рейтинга, размер ростера, парсер профиля. Третья игра добавляется одним файлом.

### Dota 2
- Роли: **1 Керри, 2 Мид, 3 Хардлайн, 4 Саппорт-роумер, 5 Фулл-саппорт**
- Рейтинг: **числовой MMR** (0–12000), плюс справочно медаль
- Профиль: ссылка на Dotabuff / OpenDota / Stratz
- **Автоверификация работает и бесплатна**: из ссылки `dotabuff.com/players/123456789` берём account_id → `api.opendota.com/api/players/{id}` → поле `rank_tier` → сравниваем с заявленным MMR → флаг `ok / расхождение / профиль скрыт`. Это и есть «проверка правильности рейтинга» для админки
- Собираем **Steam ID** — без него организаторам не собрать лобби

### League of Legends
- Роли: **Top, Jungle, Mid, ADC (Bot), Support**
- Рейтинг: **тир + дивизион** — Iron / Bronze / Silver / Gold / Platinum / Emerald / Diamond / Master / Grandmaster / Challenger, дивизионы IV–I. Выпадающий список, не число
- Профиль: ссылка на op.gg / u.gg
- Автоверификация **не делается**: Riot API требует прод-ключ с ручным одобрением. Только ручная проверка админом по ссылке
- Собираем **Riot ID вида `Nick#TAG`** и регион (после закрытия RU-сервера аккаунты живут на EUNE/EUW)

Внутри LoL тиры имеют порядковый номер — нужен для сортировки, фильтров и гистограммы. Между дисциплинами рейтинги **не сравниваются никогда**.

## 5. Данные

```
users            id, email(uniq), password_hash, recovery_code_hash, display_name?,
                 phone?, consent_152fz_at?, contact_note?, tg_chat_id?, tg_username?,
                 is_admin, created_at, last_seen_at, banned_at
game_profiles    id, user_id, game, nickname, game_account_id (SteamID / RiotID#TAG),
                 region?, profile_url?, claimed_rating, claimed_rating_ord,
                 verified_rating?, verify_status(none|ok|mismatch|private|failed),
                 verified_at?, preferred_roles[], is_looking, about
                 -- уникальность: (user_id, game)
teams            id, game, name, tag?, captain_user_id, description,
                 status(recruiting|full|locked|disbanded),
                 rating_min_wanted?, rating_max_wanted?, avg_rating(cached),
                 created_at, bumped_at
team_slots       id, team_id, role, state(open|reserved|filled), user_id?, note
                 -- reserved = «занято другом, войдёт позже»; ровно 5 слотов на команду
applications     id, team_id, user_id, roles[], message,
                 status(pending|accepted|rejected|withdrawn|auto_withdrawn),
                 created_at, decided_at?, decided_by?
invites          id, team_id, user_id, role, message,
                 status(pending|accepted|declined|expired), created_at
notifications    id, user_id, type, payload, read_at?, tg_sent_at?, tg_error?
audit_log        id, actor_user_id, action, entity, entity_id, meta, created_at
settings         key, value  -- фазы, дедлайны, инвайт-код, вкл/выкл дисциплин
```

**Инварианты:**
- Один пользователь — максимум **одна команда на дисциплину**, но может быть и в Dota, и в LoL одновременно.
- У команды ровно **5 слотов**, роли уникальны.
- Принятие заявки → все прочие `pending` заявки игрока **по этой же дисциплине** → `auto_withdrawn`, капитаны уведомляются. Иначе капитаны дерутся за призраков.
- Телефон и имя пишутся в БД **только при проставленной галочке 152-ФЗ**. Без неё — контакт через `contact_note` (Telegram/Discord/внутренний мессенджер, как игрок сам укажет).
- Телефон **не виден в общем списке**: только капитану команды, в которую подана заявка, и админам.

## 6. Экраны

**Вход в сервис**
1. Лендинг: что за турнир, **выбор дисциплины** (Dota 2 / LoL), две кнопки — «Создать команду» / «Найти команду»
2. Регистрация: почта, пароль, галочка 152-ФЗ (опциональна), экран «сохрани код восстановления». Опционально — инвайт-код организаторов
3. Профиль по дисциплине: игровой ник, Steam/Riot ID, ссылка на профиль, рейтинг, предпочитаемые роли, «о себе», как со мной связаться

**Переключатель дисциплины — в шапке.** Выбранная дисциплина сидит в URL (`/dota2/...`, `/lol/...`) и запоминается в cookie. Всё содержимое, включая админку, отфильтровано по ней. Пересечений между играми нет.

**Игрок / капитан**
4. Создание команды: название, тег, описание, разметка 5 слотов (нужен игрок / занято другом), желаемый диапазон рейтинга
5. Список команд: карточки — название, средний рейтинг состава, какой рейтинг ищут, открытые роли иконками, 3/5, когда обновлялась. Фильтры: **«моя роль»**, диапазон рейтинга, только с открытыми слотами, показывать/скрывать собранные
6. Карточка команды: состав, слоты, описание, «Вступить» → выбор одной/нескольких ролей + сообщение
7. **Свободные агенты**: игроки без команды, фильтр по роли и рейтингу, кнопка «Пригласить» для капитана
8. Мой кабинет: входящие заявки (карточка кандидата — рейтинг, ссылка на профиль, значок верификации → Принять / Отклонить), исходящие заявки со статусами, приглашения, колокольчик уведомлений
9. Управление командой: передать капитанство, кикнуть, распустить, поднять в списке (bump), закрыть набор

**Админка** (везде фильтр по дисциплине)
10. Дашборд: игроков / команд / собрано / недобор, воронка «зарегистрировался → создал или подал заявку → попал в команду»
11. Аналитика: гистограмма распределения рейтинга, дефицит ролей (сколько ищут роль X против того, сколько слотов X открыто), «ищут и не находят» с временем ожидания
12. Верификация: профили с флагом расхождения и скрытые, кнопка «перепроверить» (Dota — автоматом через OpenDota), ручной override
13. Команды и игроки: поиск, правка, бан, склейка дублей
14. **Экспорт ростеров в CSV/XLSX** — для турнирной сетки
15. Настройки турнира: фазы и дедлайны, инвайт-код, вкл/выкл дисциплин, тексты
16. Аудит-лог

## 7. Восстановление доступа (забыл пароль)

Писем нет, поэтому классического «отправим ссылку на почту» не будет. Три пути, по убыванию самостоятельности — первые два не требуют живого человека.

**Путь 1 — код восстановления (сам, мгновенно).**
При регистрации показывается один раз: `ACC-7K2M-9QX4`. Экран «Забыли пароль?» → почта + код → задать новый пароль. Код одноразовый, после использования выдаётся новый. Реально сохранят его процентов 20, но это бесплатно и закрывает часть случаев.

**Путь 2 — Telegram, если привязан (сам, мгновенно).**
Кто привязал бота для уведомлений — жмёт «Прислать ссылку в Telegram», бот присылает одноразовую ссылку на 15 минут. Для тех, у кого Telegram работает, это лучший путь.

**Путь 3 — через организатора (основной, ручной).**
На экране входа ссылка **«Не могу войти»** → форма: почта или игровой ник + как со мной связаться. Создаётся **заявка на сброс**, она падает в админку счётчиком. Плюс на этом же экране показаны контакты организаторов из настроек (Telegram / корпоративный чат) — чтобы человек не остался в тупике, если и форма не сработала.

В админке — раздел «Заявки на сброс»: список, поиск игрока по нику/почте/команде, кнопка **«Выдать ссылку для входа»**. Генерируется одноразовый токен, **живёт 24 часа, сгорает после первого использования**. Админ копирует ссылку и отправляет человеку в тот канал, из которого тот написал. По ссылке человек попадает внутрь и сразу задаёт новый пароль.

**Важно:**
- Админ **не видит и не задаёт пароль** — только выдаёт ссылку. Временных паролей открытым текстом не будет.
- Личность проверяется **вне сервиса**: человек пишет с рабочего аккаунта, организатор сверяет имя/ник/команду в админке. Это турнир, а не банк-клиент — достаточно.
- Каждая выдача ссылки пишется в аудит-лог: кто, кому, когда.
- Лимит попыток входа (5 в 15 минут на аккаунт и на IP), чтобы пароли не перебирали.
- Ссылка одноразовая и короткоживущая — если утечёт в переписку, через сутки она мертва.

**Побочный эффект, который надо ловить:** часть людей вместо восстановления просто зарегистрируется заново с другой почтой и создаст дубль. Поэтому в админке есть склейка дублей, а при регистрации проверяется совпадение игрового ника — если ник уже занят, показываем «похоже, у тебя уже есть аккаунт, вот как восстановить».

## 8. Фазы работ

**Фаза 0 — каркас и деплой (первым делом, не в конце).**
Скелет FastAPI → systemd → nginx vhost `cup.kzkovich.ru` → certbot → «Hello» по HTTPS. Чтобы деплой не стал сюрпризом на последнем шаге. *Ждём A-запись на nic.ru.*

**Фаза 1 — MVP-ядро.**
Регистрация и вход по почте с паролем, профиль по дисциплине, переключатель дисциплин, создание команды с 5 слотами, список команд с фильтрами, карточка команды, заявка на 1..N ролей, приём/отклонение, «мои заявки», авто-отзыв конфликтующих заявок, inbox уведомлений.

**Фаза 2 — двусторонний матчинг.**
Витрина свободных агентов, приглашения от капитана, bump, напоминания капитану о заявках старше суток, опциональная привязка Telegram и дублирование уведомлений в бота.

**Фаза 3 — админка и аналитика.**
Дашборд, гистограммы, дефицит ролей, «ищут и не находят», автоверификация Dota через OpenDota, ручная верификация LoL, экспорт CSV/XLSX, аудит-лог, управление фазами.

**Фаза 4 — эксплуатация.**
Ежедневные бэкапы SQLite, лок ростеров перед турниром, модерация названий и описаний, сид-данные для демо, прогон сценариев с телефона.

## 9. Деплой

```
/opt/alfacybercup/                          # код (git)
  .venv/                                    # python3 -m venv (pip3 нет, ставим через venv)
  data/app.db                               # SQLite (WAL)
  .env                                      # SECRET_KEY, ADMIN_EMAILS, TG_BOT_TOKEN?, INVITE_CODE?
/etc/systemd/system/alfacybercup.service    # uvicorn 127.0.0.1:8090, Restart=always
/etc/nginx/sites-available/cup.conf → sites-enabled/
certbot --nginx -d cup.kzkovich.ru
cron: ежедневный sqlite3 .backup → /opt/backups, хранение 7 дней
```
Отдельный системный пользователь под сервис, не root. Приложение слушает только 127.0.0.1.

## 10. Оставшиеся мелочи (не блокируют старт)

- Кто админы — список почт в `ADMIN_EMAILS`
- Нужен ли инвайт-код на регистрацию (пока делаю выключаемым, по умолчанию выключен)

- Куда уедут финальные ростеры — Challonge / Toornament / таблица (влияет только на формат экспорта)

## 11. Безопасность доступа

Пароль root пришёл открытым текстом в переписке. После настройки: SSH-ключ, отключить парольный вход, сменить пароль. Приложение в любом случае под отдельным непривилегированным пользователем.
